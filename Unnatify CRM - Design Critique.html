Diagnosis

The system has good bones.
Six things are quietly hurting it.

Most of these are inherited from leaning hard on raw MUI defaults plus a very saturated single-hue palette. None require a redesign — they're tuning, not surgery.

01Hierarchy

Everything is fontWeight 900.

h4, h5, h6, body chips, button labels, table cells — all bolded. With nothing lighter to push against, nothing reads as primary. Headings disappear into rows.

02Density

Type sizes 11.5–13.5px, rows 40px.

Compact is fine for power users, but the gap between a 13.5px h6 and 12.5px body collapses the type ramp. Headings and data look the same size.

03Color

Green carries every signal.

Status, primary action, header bg, hover, selection, sparkline, avatar, success — all the same hue. There's no way to tell "this row is converted" from "this row is selected" at a glance.

04Surface

Decoration on KPI cards.

The dashboard tiles use a soft tint, a circular before-pseudo, a pill, an icon, and a label — to display one number. That's five visual layers fighting for the value.

05Radius

Inconsistent corner system.

Theme says borderRadius: 8, but components use 1, 1.5, 1.6, 2, 4, 6, 8, 99. Pills, panels, sections, and search bars all disagree. Pick three.

06Working

What's already great.

Dark sidebar / light canvas split, the saved-views pattern, advanced filter builder, the compact data grid, and disciplined use of CSS variables for tokens. Keep those.

Leads
Principles to lock in

Six rules to prevent the next regression.

If the team agrees to these as a tiny constitution, every PR can self-check against them. They take a paragraph each to explain and an hour each to enforce in theme.ts + lint.

P · 01

Color earns its meaning.

Green is reserved for: brand, primary action, and "good" status. If you use a green tint anywhere else (hover, selection, surface), make it ≤8% opacity so it reads as neutral, not as signal.

P · 02

Three weights only.

500 for body, 700 for emphasis, 800 for headings. Drop 900 entirely — it's a punctuation, not a default.

P · 03

Three radii only.

4px for chips and inputs, 8px for cards and buttons, 9999px for avatars. Delete the others. The codebase currently uses ten different values.

P · 04

Density: one body size, 14px.

11.5 / 12 / 12.5 / 13.5 collapses the ramp. Use 14px body, 12px caption, 11px caps eyebrow. Bigger numbers (22/32) for headings.

P · 05

Status > meta > trend are different shapes.

One chip component for status (5 tones), one for meta (neutral), one for delta (trend up/down). Stop reusing AppChip for all three.

P · 06

Empty space is not wasted space.

Don't fill KPI cards with circles, badges, and icons. The number is the content. The card is just a frame.
